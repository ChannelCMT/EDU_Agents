# 原视频转写（事实层）

来源：抖音页面提供的原声转写，时长约 177 秒。本文档只作为事实核对，不直接作为最终配音稿。

## 事实摘要

- 选型核心取决于场景复杂程度和控制力需求。
- 演进路径：单 Agent → 多 Agent 协作 → 基于图的 Workflow。
- 7 种架构：单 Agent、ReAct、Plan and Execute、多 Agent、Route+Skill、Blackboard、Graph Workflow。
- 单 Agent：简单、成本低、延迟低；复杂任务容易认知过载和上下文污染。
- ReAct：Reason + Action 循环，可解释性好；Token 消耗大、不稳定，不适合大规模工程化。
- Plan and Execute：先规划再执行，稳定性高；计划错会导致全盘崩溃，灵活性弱于 ReAct。
- 多 Agent：角色分工、任务拆解清晰、上下文污染低；成本高，适合复杂行业流程。
- Route+Skill：先由意图路由器选择 Skill，再执行可复用能力；稳定、可控、可缓存、易评估，但设计成本高且可能路由冲突。
- Blackboard：多个 Agent 读写共享状态；适合复杂协作，但状态管理重、问题不易追踪。
- Graph Workflow：有向图编排，支持条件分支、并行、回溯和重试；适合生产环境和长流程自动化。
- 结论：没有最好的架构，只有最合适的架构，不必一步到位。

## 原声转写全文

如果从零搭一个 Agent 系统，你会选什么架构？很多人一上来就说 ReAct 或者 Multi-Agent，不是因为适合自己的场景，而是因为只听过这两种。这个视频把主流的七种 Agent 架构从轻量验证到企业级生产环境一次梳理清楚。
