## 本章学完能做什么

你能为“一个重要但仍以人为主的任务”选择当前最合适的模型入口，并理解为什么先追求更强推理，而不是先给弱模型叠复杂流程。

## 痛点：老板最容易卡在错误的起点

很多人一开始就在研究几十个工具、模型参数或自动化流程，却还没有稳定地用上真正强的模型。结果是：工具很多，结果不可靠；团队培训很多，关键任务仍交不出去。

## 拆解：Output 不是“回答得像人”

有价值的 Output 有三个层次：

<div class="ops-grid">
  <article class="ops-card"><span class="ops-label">01</span><h3>信息输出</h3><p>摘要、解释、提纲、灵感。适合低风险脑暴与快速理解。</p></article>
  <article class="ops-card"><span class="ops-label">02</span><h3>结构化输出</h3><p>表格、任务合同、经营报告。要求字段、证据与格式能被检查。</p></article>
  <article class="ops-card emphasis"><span class="ops-label">03</span><h3>可执行输出</h3><p>计划、文件、代码或工具调用。必须有权限边界、验收标准与人工闸门。</p></article>
</div>

模型越强，越能处理复杂判断、跨材料推理和开放式脑暴；但更强不等于可放任。Token 不是“越省越好”，而是要花在足够清楚的上下文与能减少返工的验证上。

## 学员实操：给自己一个高价值任务选“第一入口”

从第 0 章写下的任务中选一个，回答四个问题：我要交付什么 Output？它最难的判断是什么？需要哪些材料进入上下文？错一次的代价是什么？先用 Codex 或 WorkBuddy 做一次小范围试跑，不要求自动执行。

## 复盘与延伸

最强模型让你更快跨过第一道陡坡：增强现有工作。但当任务重复、复杂或风险升高，单次对话不够了。下一章要先评分，再选择合适架构。
