# 工具执行手册

这份手册说明各工具在流程里的职责。具体供应商接口可能变化，仓库只固定输入输出和验收，不把某个临时 API 写成流程真相。

## Fish Audio

输入来自批准的 `SCRIPT.md`、`tone-plan.yaml` 和 `terminology.yaml`。建议按语义段生成，保存：

- 脚本版本和文本校验值；
- 声线公开名称；
- 私有 Voice ID 的环境变量名；
- 请求时间、输出文件、时长、状态；
- 人工审核结果。

公开仓库只保留 `FISH_AUDIO_VOICE_ID`，不保留实际 ID、API Key 和个人训练音频。局部发音错误只重做对应句段。

## ASR 与逐词对齐

对齐输入必须是最终音轨。ASR 可能把 Harness 识别成 Honest，把 Config 识别成其他词；文字以批准术语表为准，时间仍以实际音频为准。

执行后检查：总时长一致、每个口播词只覆盖一次、英文/数字/转折人工复核、没有用字符密度估算替代真实时间。

## HyperFrames / GSAP

先在章节目录运行检查，再渲染：

```powershell
npx.cmd hyperframes check --snapshots --samples 15 --at-transitions --json
npx.cmd hyperframes render --quality high --fps 30 --output ".\renders\chapter-v01-no-captions.mp4"
```

实际项目应固定 HyperFrames 版本。检查报告和 contact sheet 跟 `qa-report.md` 一起保存。

实现规则：只消费通过的 `semantic-timing-manifest`；动画必须 seek-safe；进入、保持、退出分别记录；不要让旧时间线继续控制隐藏图层。

## Replicate LatentSync / 其他数字人

只用批准的开头或结尾音频做对嘴。输出 MP4 接入前先检查媒体流：

```powershell
ffprobe -v error -show_entries stream=index,codec_type,codec_name -of json .\avatar.mp4
```

如果数字人 MP4 已含音频，而页面还会播放 Fish Audio，先去掉数字人音轨：

```powershell
ffmpeg -i .\avatar.mp4 -c:v copy -an .\avatar-video-only.mp4
```

最终只能保留一条人声。

## 字幕烧录

字幕脚本消费最终音频的逐词时间和语气断句提示。先生成 `subtitle-manifest.yaml` 和 gate report，再烧录章节版。样式改变时只重烧字幕和合并，不重做动画、口型或音频。

## FFmpeg / ffprobe 合并验证

合并前所有章节必须统一分辨率、帧率、视频/音频编码。合并后运行：

```powershell
ffprobe -v error -show_entries format=duration -show_streams -of json .\final-course-video.mp4
```

确认章节顺序、总时长、H.264、AAC 和单一人声音轨，输出 `final-media-report.json`。

## 长任务的持续执行

外部 TTS、对嘴和逐帧字幕可能持续数分钟。启动时记录任务 ID、请求文件、开始时间和目标路径；等待期间持续查看状态；完成后验证产物。不要因为暂时没有新日志就启动第二份相同任务，否则容易重复扣费或产生两套音轨。
